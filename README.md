# BlueFors Heater Ramp & Data Logging System with LR700 AC resistance bridge

This repository contains a Python-based control system for automating temperature ramps on a BlueFors dilution refrigerator. It orchestrates heater control, data logging, and real-time visualization using multi-threading to ensure blocking hardware operations do not interfere with monitoring.

## File Structure

```text
.
├── Tc_check_main.py                 # Entry point: Orchestrates user input and threads
├── bftc.py                 # Driver: Interface for BlueFors Temperature Control (Scepter/MXC)
├── ramp_heater.py          # Logic: Handles the PID/Heater stepping algorithms
├── data_logger.py          # Service: Background thread for recording sensor data
├── dash_app.py             # UI: Real-time Plotly Dash web application
├── requirements.txt        # Python dependencies
└── data/                   # Default output directory for log files
```


## Module Descriptions

### `Tc_check_main.py`
The orchestrator of the workflow. It is responsible for:  
- Collecting user parameters (device name, ramp direction, power limits, timeouts).  
- Initializing the threading `Event` to control the logging lifecycle.  
- Spawning daemon threads for the Data Logger and Dash App.  
- Executing the blocking Heater Ramp logic in the main thread.

### `bftc.py` (BlueFors Temperature Control)
A hardware interface library containing low-level communication functions.  
- **Key functions:** `read_scepter_temperature()`, `read_mxc_temperature()`.  
- Used by both the logger (to record state) and the heater ramp (to make control decisions).

### `ramp_heater.py`
Contains the logic for controlling the fridge heater.  
- **Key functions:** `get_latest_heater_power_uW()`, `main()`.  
- Executes the PID or step-based ramping logic based on the user's 'up' or 'down' direction request.

### `data_logger.py`
Runs as a background daemon thread.  
- Continuously polls instruments via `bftc` and writes time-series data to disk (CSV/NPY).  
- Monitors the `stop_event` signal from `Tc_check_main.py` to cleanly finish file I/O.

### `dash_app.py`
A Plotly Dash web server running on a background thread.  
- Reads the active log files generated by `data_logger`.  
- Serves a live interactive graph at `http://localhost:8050` (default port).
